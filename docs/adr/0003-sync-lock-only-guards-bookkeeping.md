# 同步時 lock 只保護記帳，寫試算表在放開 lock 之後

每次同步在 script lock 內只做記帳：依 scanId 去重、分配 seq、預留移交紀錄上不重疊的列範圍，並在 CacheService 記下近期紀錄、已見過的 scanId、每冊最新的 seq；放開 lock 後才寫移交紀錄與 Books 的保管人。在同樣架構的報到系統上實測，lock 內讀寫試算表一次要持有約 1.3 秒，8 個入口同時同步就排隊到逾時；只記帳時持有時間 p50 約 0.3 秒。

寫保管人前比對快取裡這一冊最新的 seq，已被更新的移交取代就不寫。兩批同步放開 lock 後的寫入順序可能顛倒，不比對的話舊的保管人會蓋掉新的。

## Considered Options

- **在 lock 內寫保管人**：沒有任何競態，但持有時間回到 1 秒以上。比對與寫入之間的空窗只有幾十毫秒，而且只在兩個入口幾乎同時移同一冊時才有影響，不值得。

## Consequences

- 已見過的 scanId 與每冊最新的 seq 存在 CacheService：快取被清掉後重送的移交可能多寫一列，比對也可能失效。重送的移交結果相同，所以接受。
- 預留的列範圍若不是空的（有人手動插入或刪除了列），那一批改在 lock 內接在最後一列之後寫，並校正計數器。
- 同步回應的 `entries` 只涵蓋最近 300 筆。
