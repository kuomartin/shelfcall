# shelfcall

書籍保管登記：Books 分頁記錄每一冊書由哪個班級保管。老師在掃描頁選定保管人後連續刷書，掃描頁在本機立刻判定，Apps Script 批次寫入並同步各入口。

用語見 [CONTEXT.md](CONTEXT.md)，設計決策見 [docs/adr/](docs/adr/)。

## 給管理者

### 試算表

`Books` 分頁第 1 列是標題，程式依標題名稱找欄位，欄位順序不拘。

| 欄位 | 必要 | 說明 |
|---|---|---|
| 主條碼 | 是 | 每冊一個、不可重複。欄位格式要設成「純文字」，否則 `000070` 會被存成 `70`，刷條碼時對不到 |
| 書名 | 是 | 刷書時顯示 |
| 保管人 | 是 | 班級名稱或「學校」，要和設定裡的保管人清單一致。程式會改寫，也可以手動修改 |
| 更新時間 | 否 | 有這一欄的話，程式寫入保管人時一併寫入時間 |

其他欄位（ISBN、作者、分類……）程式不讀也不寫。`移交紀錄` 分頁由程式建立與寫入，不要手動編輯。

Books 上不要放引用 `移交紀錄` 或保管人欄的公式，也不要用 `NOW`、`TODAY`、`INDIRECT`、`OFFSET`：每次同步寫入都會觸發重算，同步會變慢。統計放到另一份試算表，用 `IMPORTRANGE` 讀資料。

### 第一次設定

1. 在試算表「擴充功能 → Apps Script → 部署 → 新增部署作業」，類型選網頁應用程式，執行身分「我」，存取權「所有人」。
2. 用瀏覽器開一次部署出來的網址，依指示授權，看到「已完成初始化」。
3. 回到試算表，選單「保管 → 設定」填入保管人清單（「學校」一定在清單裡）。
4. 選單「保管 → 檢查書目」：列出沒有條碼、條碼重複、條碼存成數字、保管人不在清單裡的列，修正到沒有問題為止。
5. 選單「保管 → 工作人員連結」，把連結或 QR code 交給老師。

### 刷書

- 先在頁面上方選保管人，之後刷的每一本都移到這個保管人名下，直到改選別的。還書就是選「學校」再刷。
- 三種結果各有不同的提示音：移交（高音一聲）、已在這個保管人名下（兩聲）、找不到條碼（低音）。
- 刷錯了，在「最近刷過」按「復原」，書會移回原本的保管人。書之後已被移到別處時不能復原。
- 可以用相機掃 QR code、Code 128、Code 39，也可以接 USB 條碼槍或直接輸入條碼。
- 多台裝置可以同時刷。離線時禁止刷書。

## 結構

| 目錄 | 內容 |
|---|---|
| `core/` | 純 TypeScript 領域邏輯：書目快取、刷書判定、同步、請求驗證。不依賴 Apps Script 或 DOM，用 `node --test` 測 |
| `gas/app/` | 綁定試算表的 Apps Script：Web App API、選單、對話框 |
| `web/` | 掃描頁，GitHub Pages 提供（`main` 推送後由 `.github/workflows/pages.yml` 部署） |
| `scripts/build.ts` | esbuild 打包，輸出到 `dist/` |

Apps Script 只認得頂層函式，所以建置時會替 `gas/app/main.ts` export 的每個函式，在檔尾補一個同名的頂層函式。

## 指令

```bash
npm test
```

```bash
npm run typecheck
```

```bash
npm run build
```

推送 Apps Script 用 `npx clasp push`，`.clasp.json`（不進版控）的 `rootDir` 指向 `dist/gas/app`。`npm run build -- --dev` 的建置多出端到端測試用的 `devReset`（清空移交紀錄、設定保管人清單）與 `devDump`（讀回移交紀錄與指定條碼的保管人）。
